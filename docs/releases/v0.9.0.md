# AkuBrowser v0.9.0

Status: **stable Windows x64 release**. This release is scoped to one
intentionally unsigned installer `.exe` plus its SHA-256 checksum. Windows may
show a SmartScreen warning; verify the checksum before running it.

## Distribution

The installer contains one complete installed-app tuple:

- AkuBrowserLauncher and its Windows application identity;
- AkuSidecar and the local loopback app shell;
- the internal `production-app` AkuBridge payload;
- the pinned Chromium build and isolated profile boundary;
- c2patool, release configuration, manifests, and checksums.

The active path does not use the Chrome Web Store, system Chrome, Developer
Mode, manual extension loading, or a separate runtime installer. Chrome Web
Store publication is frozen. macOS and Linux are deferred and are not v0.9.0
assets.

## Highlights

- Four source adapters are covered by the release contract: X, LinkedIn,
  Facebook, and opt-in Instagram.
- AkuSidecar uses database schema 22 with the documented additive migration
  boundary from schemas 7 through 21.
- Codex App/App Server remains an external prerequisite and the authoritative
  baseline for model-backed checks.
- The optional Gemini provider accepts a user-supplied key through the Sidecar
  credential flow; provider hot-swaps take effect at an idle boundary.
- AkuSidecar owns first-run onboarding, source readiness, calibration, Timeline
  state, and the local data/reset boundary.
- AkuSupervisor remains development-only and is not bundled.

## Verification and known limitations

Automated release checks cover the complete tuple, exact identity, payload
hashes, Sidecar/Bridge contracts, launcher, and installer PE structure. The
following independent clean-machine coverage remains open hardening work:

- installer checksum, disclosed unsigned state, and SmartScreen/antivirus behavior;
- clean-machine install and launch without system Chrome or Developer Mode;
- exact `production-app` identity, pinned Chromium payload, and healthy
  Bridge/Sidecar heartbeat;
- source permission, sign-in readiness, denial/retry, and revocation for the
  exercised adapters;
- Codex readiness, Gemini-key use, and an idle-boundary provider hot-swap;
- schema-22 startup/migration behavior;
- repair, restart, update/rollback, ordinary uninstall with data preservation,
  and explicit full reset.

Code signing, whole-tuple automatic update/rollback, and independent
clean-machine certification are not claimed by v0.9.0. Users must verify the
published SHA-256 and must not disable security protection broadly.

## Historical lanes

The Chrome Web Store package, companion runtime installers, and portable ZIPs
remain documented as historical/recovery lanes. They are not updated or
published as part of v0.9.0.
