# AI Feedback Engine contract

Status: canonical personal AI-feedback boundary, 26 July 2026.

## Purpose

AkuBrowser does not promise an objective detector of whether all social content
was generated by AI. It combines bounded origin signals and gives the user the
highest authority over how those signals are presented in their own local
experience.

The AI Feedback Engine is separate from the Preference Engine:

- preference evidence answers **what this user wants to spend attention on**;
- AI feedback answers **how this user wants an origin/provenance assessment
  interpreted and routed**;
- AI feedback may change a badge, AI Signals drawer routing, or bounded Deep
  review priority;
- AI feedback must never change candidate ranking, selection, Timeline capacity,
  topic/facet weights, or More/Less learning.

## Three safe stages

### 1. Object-scoped feedback metadata

The AI badge exposes three verdicts:

- `ai`;
- `not_ai`;
- `unsure`.

Every event names exactly one target and matching signal scope:

| Target | Signal scope | Meaning |
| --- | --- | --- |
| `post` | `social_post` | authorship/origin of the social-post text |
| `media` | `attached_media` | attached image or, later, video |
| `quote` | `quoted_post` | quoted or embedded social content |
| `account` | `author_account` | an explicit rule for the captured account identity |

The optional reason is a bounded vocabulary: author disclosure, platform label,
Content Credentials/C2PA, explicit agent identity, repeated automated pattern,
signal attached to another object, known human authorship, or insufficient
evidence. Style alone is not a canonical reason.

`Unsure` is not a weak `not_ai` verdict. It leaves current detector evidence
inspectable and immediately queues one bounded Deep Detection review for that
item when AI Detection is enabled. While the job is pending, the personal
request has first shortlist priority and does not route an otherwise-neutral
post into the AI drawer. Once a newer Deep assessment is durable, the request
is considered fulfilled and the badge reflects that assessment; the original
`unsure` event remains in the append-only history.

### 2. Canonical append-only ledger

`ai_feedback_events` is the canonical personal evidence ledger. Detector output
continues to live separately in `ai_assessments`; model or deterministic
detectors cannot write user authority.

Undo never mutates or deletes the earlier event. It appends a `clear` event that
supersedes the active decision for the same target. The UI can inspect the full
event history, including clears.

Ledger insertion order is the causal authority when feedback from different
object scopes must be resolved. Wall-clock timestamps remain reader-facing
telemetry only; equal timestamps can occur on Windows and random event IDs must
never decide which user action wins.

Post, media, and quote feedback follow the configured local retention boundary.
Explicit account rules are retained until cleared or Reset learning/full reset
because they are deliberate durable policy rather than an inference from one
post.

### 3. Personal AI Policy

Personal AI Policy is a deterministic projection over the latest canonical
feedback for the current item:

1. the newest active post/media/quote event for that native evidence identity;
2. otherwise, an explicit account rule for the same source and normalized
   captured author identity;
3. otherwise, detector/platform/media provenance resolution alone.

Exact object feedback is more specific than an account rule. No account rule is
ever inferred from repeated item corrections; the user must explicitly select
`This captured account`.

An `ai` policy routes the item to AI Signals. A `not_ai` policy only suppresses
signals in its own object scope: marking attached media as not AI cannot erase a
strong social-post authorship signal, and marking post text as not AI cannot
erase direct C2PA media provenance. An account policy applies to post/account
origin signals but not to unrelated attached-media provenance.

## Parallel with preference learning

Both engines follow the same safe structural pattern:

```text
append-only user evidence
        -> canonical latest-event resolver
        -> deterministic derived projection
        -> bounded serving behavior
```

They deliberately use different evidence and outputs:

| Boundary | Preference Engine | AI Feedback Engine |
| --- | --- | --- |
| Input | More/Less, calibration, selection correction | AI/not-AI/Unsure, scope, optional reason |
| Features | topic tags and facets | object scope, source identity, account identity, evidence family |
| Projection | preference profile/model | Personal AI Policy |
| Generalization | broad but bounded topic/facet affinity | exact object; explicit account rule only |
| Serving effect | rank/promotion/guarded filtering | badge/drawer/Deep-review priority |
| Main failure risk | filter bubble or missed interests | false AI attribution or hidden human content |

The Personal AI Policy is therefore not stored inside `preference_model` and is
never passed to selection scoring.

## API and lifecycle

- `POST /api/timeline/{id}/ai-feedback` appends a scoped verdict;
- an enabled `unsure` verdict queues item-scoped Deep Detection asynchronously
  without blocking the feedback response or Timeline;
- `GET /api/timeline/{id}/ai-feedback` returns inspectable matching history;
- `POST /api/ai-feedback/{id}/undo` appends a superseding `clear`;
- Reset learning clears AI feedback alongside preference evidence;
- full reset clears the ledger and restores product defaults.

SQLite schema 7 is the fresh boundary that separates detector assessments from
personal AI evidence. There is no migration or compatibility importer from
schema 6.
