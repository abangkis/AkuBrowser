# AkuBrowser v0.9.0 RC8 (Windows x64)

This prerelease continues the v0.9.0 product line. The intentionally unsigned
installer contains AkuBrowser 0.9.0, AkuSidecar 0.9.0, and AkuBridge 0.9.2
(Chrome manifest 0.9.2.0; `source-adapters-v111`). Bridge has a separate version
because its new service-worker entrypoint replaces the stale worker on upgrade.

RC8 includes Sidecar schema 29 and defaults new Windows tuples to split capture.
The ordinary launch path remains available as the split runtime rollback choice.

Source commits: AkuBrowser `42ac9958044870f96ce9bbaa102003c24b80b0c7`,
AkuSidecar `46b4a6142659a25d5b0a1d62e63b614e6630dfc5`, AkuBridge
`62fd01b03c2dc2dc41327f37ddcdcdb14bcf1346`.

Installer SHA-256: `b3270aae847ac08a8bcbdd788312802316f42ee7b21eb3c0866a30f2db02c3b0`.
Verify the adjacent `.sha256` file before running. Windows SmartScreen or
antivirus may warn because the installer is unsigned.

Automated source, tuple, checksum, and installer-structure checks passed.
Independent clean Windows x64 fresh-install and preserved-data upgrade tests
remain open because no clean VM/account is available. Repeated visible capture,
automatic startup recovery, capture-host presentation, and packaged
shutdown/rollback remain open in the capture split graduation matrix. A local
development canary does not prove these installer behaviors. Database schema
rollback to an older RC is not implemented; back up important data before an
upgrade trial.

The earlier `v0.9.0` release/tag is untouched. Chrome Web Store publication
remains frozen; macOS and Linux are deferred.
