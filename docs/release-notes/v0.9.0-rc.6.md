# AkuBrowser v0.9.0 RC6

Windows x64 prerelease candidate built from the clean source commits below. The installer retains application version 0.9.0 under the existing RC packaging convention.

## Changes since RC5

- Installed-app startup now has a native status window with diagnostics and a manual **Retry window** action when the interface does not acknowledge startup. In a fresh-profile acceptance run, the first Chromium window remained white; one user-triggered retry closed that window, launched a replacement, and displayed onboarding without creating a second Sidecar instance. This is a recovery path, not a proven fix for the first-launch cause.
- The installed-app shutdown path now closes the Sidecar cleanly when the browser exits, including when the native status window was closed first.
- Database preparation handles older schemas through compatibility classification and guarded keep, fresh-start, or migration choices, rather than a one-off schema fix. The local schema-24 migration fixture preserved its backup and reached schema 25; installer-upgrade acceptance remains open.
- Onboarding provides isolated-profile sign-in guidance, clearer source-access and reasoning-provider readiness, Gemini API-key setup guidance, and fail-closed provider selection when credential confirmation is incomplete. Facebook session continuity across normal restarts and two local builds was accepted; a real Gemini key and quota were not tested.
- AkuBridge recovers its relay after transient onboarding navigation.

## Distribution and known limits

The installer contains AkuBrowserLauncher, AkuSidecar, the production-app AkuBridge payload, pinned Chromium, c2patool, configuration, and checksums. Verify the accompanying SHA-256 before running it. The installer is **unsigned**; code signing, whole-tuple automatic rollback, and independent clean-machine certification remain open hardening work.

Four installation/onboarding acceptance items remain open: legacy-database handling through a real installer upgrade (INST-01); first-launch white window and post-onboarding Chrome-banner acceptance (INST-02); uninterrupted first-run journey through Grant access (INST-03); and real Gemini key/project/quota validation (INST-05). Isolated-profile login continuity (INST-04) is complete in the selected scope. Avast is present on both affected devices but is **not established** as the cause of the white window. Codex App/App Server remains an external prerequisite; Gemini is an optional user-configured provider.
