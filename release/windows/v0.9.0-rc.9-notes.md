# AkuBrowser v0.9.0 RC9 (Windows x64)

RC9 is an intentionally unsigned prerelease on the 0.9.0 product line. It
contains AkuBrowser 0.9.0, AkuSidecar 0.9.0, and AkuBridge 0.9.2
(Chrome manifest 0.9.2.0). The installer filename retains the three-part
product version: `AkuBrowserSetup-0.9.0-windows-x64.exe`.

## Change since RC8

The source commits document RC8's partial installed-app acceptance and clarify
how to recover a development Sidecar database after a newer runtime wrote it.
The development restart script is not part of the installed application.
The packaged AkuBrowserLauncher.exe and AkuSidecar.exe have the same SHA-256 as
RC8. RC9 does not contain an application fix for Avast One AutoSandbox. The
Facebook `login_required` result occurred before the preserved capture profile
completed a two-factor sign-in flow. The installed RC9 retest completed a
Facebook capture after that sign-in, supporting an authentication-timing cause
rather than an adapter change.

## Open acceptance gates

The RC8 [installed-app receipt](https://github.com/abangkis/AkuBrowser/blob/fb445b230762d90f9caeaa25270ac3e935427e7b/acceptance/windows-installed-app-rc8-2026-09-23.md)
is partial. RC9's local test used the same existing Windows account; it is not
independent clean-machine evidence. The user reported removing the temporary
Avast exception before the test, but its configuration was not independently
verified. UI-shell visual behavior, repeated split-capture focus containment,
and database rollback to an older RC remain unverified. The RC9 application
binaries are unchanged from RC8; a successful local retest must not be read as
an Avast or Facebook code fix.
Chrome Web Store publication remains frozen; macOS and Linux are deferred.

The existing `v0.9.0` and `v0.9.0-rc.8` releases remain unchanged.
