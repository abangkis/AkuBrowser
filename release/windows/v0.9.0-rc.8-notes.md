# AkuBrowser v0.9.0 RC8 (Windows x64)

This prerelease continues the v0.9.0 product line. Its intentionally unsigned
Windows installer contains AkuBrowser 0.9.0, AkuSidecar 0.9.0, and the separately
versioned AkuBridge 0.9.2 (Chrome manifest 0.9.2.0, runtime
`source-adapters-v111`). The newer Bridge manifest replaces the previous
service-worker entrypoint during extension upgrade. The product version does
not follow the Bridge component version.

RC8 includes the schema 29 Sidecar candidate and makes the split capture
runtime the default for new Windows tuples. The ordinary launch path remains
available as the split runtime rollback choice.

## Verification and limits

The published installer and adjacent `.sha256` file are built from the exact
three repository commits recorded in the generated tuple manifest. Automated
checks cover source identity, component tests, tuple contents, checksums, and
installer structure. Check the SHA-256 before running the installer. Because
the installer is unsigned, Windows SmartScreen or antivirus may warn.

Independent clean Windows x64 fresh-install and preserved-data upgrade tests
remain open; no clean VM/account is currently available. Repeated visible
capture behavior, automatic startup recovery, capture-host presentation, and
packaged shutdown/rollback also remain open in the capture split graduation
matrix. A local development canary does not prove these installer behaviors.
Database schema rollback to an older RC is not implemented. Preserve a backup
before testing an upgrade with important local data.

The existing `v0.9.0` release/tag is historical and remains untouched. RC8
does not overwrite or promote that tag. Chrome Web Store publication remains
frozen; macOS and Linux are deferred.
